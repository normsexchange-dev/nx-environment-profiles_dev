# Environment operating-profile architecture

The operating profile is a contract between one-time genesis and runtime-specific execution. It defines durable functions without claiming that a particular model, chat surface, or application implements them.

## Authority order

Platform and system constraints remain highest. Owner policy and environment constitution govern identity, repositories, privacy, and capabilities. The environment profile supplies neutral infrastructure semantics. A runtime adapter only translates discovery and reports evidence. Agent families add job knowledge. Missions add standing purpose. Goals add bounded work and explicit external authority. Private memory is last and is never copied as infrastructure.

No lower layer silently overrides a higher one. In particular, an agent family cannot create repositories, grant credentials, enroll itself, publish an external message, or turn an application database into the authoritative operations store.

## Provision once, enroll repeatedly

Persistent infrastructure is provisioned once per sovereign environment. Discovery resolves existing repository functions before proposing creation. Every agent has a distinct truthful identity, may hold multiple project-scoped enrollments, and joins through an owner-authorized enrollment record. New agents never copy another agent's identity or private memory and never duplicate control or operations repositories.

One environment may contain several runtimes, agents, roles, projects, families, missions, and goals. A runtime or family is not an identity. An enrollment is not a global role.

## Backend neutrality

The profile speaks in logical repository functions, immutable records, compare-and-swap lease views, reader-owned state, evidence-backed capabilities, and publisher-owned channels. GitHub is the first backend contract. A future backend may conform only if it preserves the same semantics, authority stops, identity boundaries, immutability, and recovery properties.

## Sovereignty

The profile publisher owns the immutable public standard. A destination owns its environment after adoption. It may adopt, reject, defer, fork, or specialize a profile. Compatibility verification never adopts on its behalf, grants access, or evaluates unrelated sovereign application state.
